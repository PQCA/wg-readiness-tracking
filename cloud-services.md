# Cloud Services PQC Readiness

This page tracks the Post-Quantum Cryptography (PQC) readiness of major Cloud Service Providers (CSPs) and Edge/CDN platforms.

Because cloud platforms encompass distinct infrastructure layers that mature on independent timelines, readiness is tracked across four functional cryptographic planes:

1. **Key Management & Cloud HSM Services (KMS / HSM)**: Customer-managed keys (CMKs) for key encapsulation (KEM), envelope encryption, digital signatures, and key import (BYOK).
2. **Edge, CDN, Load Balancing & API Ingress (Data-in-Transit TLS)**: Hybrid PQC key exchange in TLS 1.3 and HTTP/3 (QUIC) for ingress负载均衡, CDN edge termination, and service API endpoints.
3. **Cloud PKI, Certificate Authorities & Artifact Signing**: Managed Private/Public Certificate Authorities (X.509 and Merkle Tree Certificates) and managed code/artifact signing services.
4. **Cloud Interconnect, VPN & Service Mesh (Network Transit)**: Post-quantum IPsec VPNs, hybrid cloud interconnects, and internal service-to-service mesh encryption.

---

## Readiness Criteria

To be considered **Ready** within a specific cloud plane, a service must meet the following criteria:

* **Inventory & Visibility**: Provides mechanisms (such as cloud audit logs, TLS connection telemetry, or key inventory APIs) to inspect negotiated PQC cipher suites/groups or catalog PQC key/certificate assets.
* **Algorithm Support**: Supports NIST-standardized PQC algorithms — **FIPS 203 (`ML-KEM`)**, **FIPS 204 (`ML-DSA`)**, **FIPS 205 (`SLH-DSA`)**, or **SP 800-208 (`LMS`/`HSS`/`XMSS`)** — or IETF-standardized hybrid constructions such as **`X25519MLKEM768`**, **`SecP256r1MLKEM768`**, or **`X-Wing`**.
* **Cryptographic Agility**: Enables customers to configure TLS policies, rotate keys/certificates, or migrate between classical, hybrid, and pure PQC algorithms via standard APIs/IAM policies without re-architecting applications.

### Status Definitions

* **Ready**: General Availability (GA) support for NIST-standardized PQC algorithms (or IETF-standardized hybrids) in the specified service plane.
* **In Progress**: Public Preview, Beta, experimental support, or partial plane coverage (for example, software-backed KMS keys are GA while FIPS 140-3 hardware-backed HSM support is still in development).
* **Planned**: Publicly committed on the provider's technical roadmap or standards track, with no customer-accessible preview yet.
* **Not Started**: No publicly documented PQC support or technical roadmap for this service plane.
